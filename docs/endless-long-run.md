# 無限供給・比較盤面の長期確認

2026-10-11、ca7d97aのゲーム実装を確認。36×27・敵24体は仮の比較サイズのままです。ゲームコード・バランスは変更せず、検証スクリプトと証拠だけを追加しました。

seed 20261011と11に限定し、各方針12秒の実時間上限・43,200tick上限で、通常入力が呼ぶ `place` / `step` を加速実行。敵周辺の合法候補を予測攻撃・被害で評価する攻撃方針と、敵が8体以下になった後は敵から7以上離れた場所へ配置する残存方針です。配置力や個体を人工的に追加していません。候補の全盤面探索は人間より有利なため、攻略難易度や人の所要時間の評価ではありません。

最終4runの実行時間は合計約16.8秒。残存方針は攻略を保留する意図的な遊び方ですが、到達状態は通常のルールだけで作りました。人工負荷fixtureは今回使っていません。旧 `long-run-save.mjs` の24ゲーム時間検証は有限供給・基準盤面なので、新しい無限供給の長期保証には流用していません。

約200個体のrun全体のtick時間95%点は0.335 / 0.416ms。最大2.33 / 86.65msで、後者に単発の外れ値があります。原因は断定していません。既存の自然な最大残存checkpointだけを再利用した20回の追加測定では、遅いtickは最大2.13ms、capture＋checksum＋RunStore.writeは95%点約2.00〜2.02ms、read＋検証は約4.10〜4.90msでした。後者の保存先はNodeのMapで、ブラウザの永続ストレージ時間とは別です。履歴は64件、全個体・queue・時刻の復元は完全一致。保存安全上限2MB・2,048個体より十分小さい範囲です。

隔離Edge154で自然な残存checkpointをPC1366×768 / touch設定390×844へ読込み、通常ボタンで1tick、4倍速、停止、再読込、再開、手動終了を確認しました。全体表示のフレーム間隔95%点は約33.5〜33.6ms（約30fps）、局所ズームの進行中は約16.8〜16.9ms（約60fps）。全体表示では停止中にも約30fpsでした。進行中の最大はPCのseed11で50.3msが1回、他は約33.5〜33.6ms。PerformanceObserverのlongtaskは0、実行時エラー0。全体表示の描画低下は実測した制約ですが、固まり・データ欠落・復帰失敗は再現せず、今回の承認範囲でゲーム実装を追加していません。ブラウザのlocalStorage.setItem単体は最大0.7ms（JSON生成は含みません）。

seed11の通常攻撃runでは、味方0体の状態が90tickあり、その後攻略に復帰しました。その自然checkpointをUIへ戻し、味方0・配置力2から通常タップで1体配置できることを確認。無限供給での味方全滅は自動敗北にせず、配置を続けられる現在の挙動です。配置力0の自然な残存checkpointでは、停止中の補充までのゲーム秒表示、時間送りで配置力回復、敵数不変を確認しました。攻略完了は結果表示と操作無効化、手動終了はlossの結果表示になります。一時停止のtick維持、背景中のcatchupなし、再読込時に停止状態で全stateを復元する確認も通過しました。

実機スマホ・Safari、実時間72分/24時間のブラウザ放置、多数味方＋多数敵が密集して撃ち合う状態、2,048個体近辺は未検証です。今回は必要な自然状態までで止めています。大量追加や長いsweepは行っていません。

ユーザーテストを待つ論点は、24敵の盤面を回る操作感、24ゲーム秒補充待ちと全滅後の再配置が伝わるか、攻略完了後の見せ方、全体約30fpsが実機で許容できるかです。比較サイズの確定・難易度・供給間隔はこの検証で決めません。次の既存承認内の実装余地は、ユーザー操作で再現したUI不具合の修正、必要性を測定できた場合のシミュレーション意味を変えない局所描画改善です。今すぐ修正すべき再現不具合は残っていません。新ルール・新システムを足す前にユーザーの試遊を優先します。
