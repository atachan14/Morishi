# 0基準移行の最小判断案

確定済み: M(x)=1+x/100 (x>=0)、1/(1-x/100) (x<0)。size0半径100、Aura/根の0は本体外周から200。再質問しない。

推奨は旧runの実効値Eを保ち、m=E/Baseから補正へ逆変換する。m>=1で100(m-1)、0<m<1で100(1-1/m)。旧size100%（半径50）は補正-100。半径50・旧根外端100なら根到達50で補正-300。旧Aura10は-1900。新規初期値も初めは現行seedの実効値を変換して継承する案が最小で、補正0付近へ一斉変更する新分布は別判断。

実効0は有限補正で表せないので、補正とは別にStatのゼロ/有効状態を保存する案を推奨。例: state=zero（実効0、補正なし）、state=scaled（補正0ならBase実効値）。Skillの習得・使用可能状態とは別で、Power0でも習得済みSkillは無駄撃ち可能。根の本体内範囲や旧中心距離Auraは、ゼロ状態だけでは互換にできず旧幾何モデルの保持も必要。未決定のため今回は状態形式を実装しない。

Base40ならPower40→補正0、20→-100、80→+100。成長40→41は補正+2.5。合体40+20→60は補正+50。補正値の直接加算0+(-100)は実効20となり互換でない。本体半径50+50の面積合成は70.710678、size補正約-41.421356。根外端100+100の面積合成141.421356に対し、合体後本体からの到達70.710678は根補正約-182.842712。

現行root合体はeco-v2-root-merge.mdで実効Stats加算、size再乗算なしと明記。eco-v2.mdにも現在ElementStats全加算と再倍率防止を記録。今回読んだdocsでは、この算式を明示承認したユーザー原文は見つからなかったため、既存実装と継承方針の証拠として扱い「新しい明示承認が済んだ」とは言わない。根半径の面積加算は同文書で仮ルールと明記されている。

根モードは既にsize成長後にStatsを再乗算しないため、実効演算後の逆変換を採ればsize倍率廃止と整合する。通常percentモードは依然としてsize倍率があるので別移行が必要。初期root登録は旧percent実効値を出生時に保持しているため、旧seed.rawだけを新基準で解釈してはならない。

最小判断は「既存実効値を維持する移行を採用するか」「ゼロ状態と旧幾何モデルを許容するか」。成長/合体は互換案として現行実効演算を保ち、補正へ直接加算する新仕様を勝手に実装しない。Power等のSkill Base、新分布、Tech水分コスト、Aura候補0下限は未決。

数値はfloat64。逆変換は近似誤差を持つため相対/絶対許容誤差を併用して検証し、UI丸めを保存へ戻さない。極端に小さい値は割算アンダーフローや補正値オーバーフローで表せない場合がある。失敗を明示し旧原本を保持する。負補正でも実効値は正、Aura地点強度の負値は別の意味で維持。
