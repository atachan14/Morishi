基準12×9・敵7体の盤面を維持した、次の規模を試す土台。正式な広さ・敵密度・難易度は未決定。通常の起動は引き続き基準盤面です。新規runはユーザー承認の「配置力は時間で回復、ユニット供給は尽きない」を採用しました。P=2 / X=1.5 / 24ゲーム秒補充 / 最大配置力5 / 敵攻略+1 は据え置き。旧Unityと原文記録は保全。

## ステージ設定と表示

`src/stage.ts` のStageConfigは width / height / enemyCount。基準設定では従来の7座標・seed変動・能力列を保持。別設定では、生成時だけseed由来の連続座標で配置し、全敵は最初から存在します。有限の格子骨格と小数ジッターを用いる検証用生成で、正式なランダムステージ設計ではありません。成熟時の非重複と盤面内の配置を保つ密度条件を事前検査し、退避点は既存の有限補正で検査します。技術上の範囲（寸法6〜256、敵1〜256）は難易度の決定とは別です。

配置境界、面積近似、client座標変換、camera clamp、開始注視、全体表示、攻略数/初期数、保存検証はそのrunの設定を参照します。カメラ上限倍率は規模に応じて拡大し、局所で植物が小さくなりすぎることを避けます。禁止面は現在の表示範囲内を96×72で近似し、view変更時にもcacheを更新。盤外の個体描画を省きます。配置判定は引き続き合計存在感の解析値です。最初から配置可能な面積が広い場合があり、その%は攻略率とは区別します。

検証用例: `createState(seed, {width:36,height:27,enemyCount:24}, 'endless')`。後続で比較選択を観察Pane上部に追加しました。入口と履歴上限後の確認は [entry-tail.md](entry-tail.md) を参照。

## 尽きない供給、有限の保存

新規runはsupplyMode=endless、消費索引supplyIndex、先読み4体（現在+次3）を保持。配置で索引を進め、seed+初期敵数+索引から次の能力を再現。最初の18体は従来の能力列と一致し、それ以降も同じ索引は同じ能力です。非常に遅い索引でも、過去の全供給を再生しません。能力種別や値の範囲、新資源は増やしていません。時間による配置力回復が配置の予算になります。味方全滅だけでは敗北せず、回復後に再配置できます。敵全滅の攻略完了、任意run終了は維持。

新供給では各生存味方に生成索引と配置tickを持たせ、能力・ID・年齢を直接検証して復元します。供給キューは4体、保存する入力履歴は直近64件。使われなくなった味方領域履歴は新供給runでは蓄積せず、敵撃破記録は初期敵数内に収まります。履歴が欠けたから供給を巻き戻すことはありません。

snapshot-6を使用。生存盤面には有限の技術予算（2048個体/記録、UTF-8 2MB、読込操作列1024件）を設け、供給の有限18体制限とは分離。書込時も予算を検査し、超過時は最後の良好保存を上書きせず、既存の停止/保存失敗表示で保護します。生存個体が増えるほど保存・戦闘計算は増えるため、無限個体や全端末性能を保証する方式ではありません。

同ルールのsnapshot-3/4は12×9・7敵・finiteとして補完し、残りの旧18体在庫、HP、tick、viewを保持します。途中のsnapshot-5設定形式も有限runとして扱います。旧runを再開しただけでは供給方式は変えません。明示的な新seed/入力seed開始からendlessになり、前保存は従来どおり退避されます。異なるルール・破損保存は引き続き保護し、黙って再解釈しません。
