# 敵100体・初期生成範囲

原因はradius入力・createV2Game内部レイアウト・保存検証の上限1400。加えて敵数24固定、nextId25、由来ID/報酬24の保存制限があり、100体と広い円を生成しても保存できなかった。

新規CURRENTは敵100体、手札/敵サイズは既存100〜140%、半径2400、最小外周間隔40。初期味方0。半径は200〜100000を共有定数から入力/生成/保存に適用。面積一様の sqrt(U) を維持し、体と間隔が重なる候補を棄却する。旧metadata省略は敵24体・既存半径として読み、再解釈しない。既存runを保持したまま、次の新規作成のSettings半径候補は最低2400へ広げる。

小さすぎる半径は必要面積を先に検証。残る密配置の失敗は各個体1024候補、全体8レイアウトまでで止める。Setting内に半径を広げる案内を表示し、失敗時に既存state/primary保存を更新しない。旧runからの成功した新規生成はpreviousキーへ退避。全100由来ID・100報酬・以後の手札強化が保存可能。総生存数上限128は維持。

負荷対策: 成長/合体完了後に同一tickの実効値を共有し、攻撃/回復の判定・軽減・HP上限で再計算を減らす。同時効果の意味は維持。単一Nodeプロセス、敵100+味方1、100tick: 平均5.30ms、p95 6.15ms、生成13.23ms、保存203952bytes、復元18.47ms。密な半径800は45.88msで安全に失敗。長時間のメモリ測定ではない。

検証: 250 tests成功、型検査/Vite build成功（既存Phaserチャンク容量警告）。24 seed×100体の非重複/外周間隔/円内収容/径別面積一様性、半径1600/2400/4000/12000/100000の生成保存、無効値と密配置、旧24体保存、全100報酬、配置ID101以降、進行と復元を確認。
