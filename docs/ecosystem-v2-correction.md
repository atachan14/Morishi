# 0基準倍率と承認済み幾何基準の先行実装

実装: src/eco-v2-correction.ts。モデルzero-correction-geometry-1。

M(x)=1+x/100 (x>=0)、1/(1-x/100) (x<0)。有限負値で正倍率を保持。非有限値、実効値のオーバーフロー、逆変換不能値は明示的に拒否し、ゲーム数値を勝手に丸めたり上限へ置換しない。

- 本体半径 = 100×M(size補正)
- Aura外周からの到達距離 = 200×M(Aura補正)
- Aura地点強度 = 到達距離−max(0,中心距離−本体半径−候補半径)
- 根外周からの到達距離 = 200×M(root補正)
- 根外端の中心距離 = 本体半径＋根到達距離

全補正0なら本体半径100、Aura到達200、中心距離299の地点強度1、根外端300。size-100で半径50、+100で200、+200で300。Aura地点値の負値はそのまま返す。発動条件・対象順位へ新しい0下限を追加しない。

geometryDisplayはcorrections/effective/pointStrengthを別項目で返すUI向け投影API。補正0、実効到達200、地点強度1を混同しない。今回は本体UIやプレイモデルへ接続せず、現在の庭は旧表示・旧計算で動く。UI幅/高さの前コミットも維持。

## 既存実効値の維持

m=実効値/Base。m>=1では補正100(m−1)、0<m<1では100(1−1/m)。旧size100%は直径100・半径50なので新補正-100。旧Aura10は補正-1900。旧本体半径50・根外端100なら根到達50なので補正-300。

根保存の各Plantを投影し、本体半径・Auraの符号付き距離曲線・根外端を維持。根は旧stats[root]×config.radiusPerPointを実半径として読む。未登録の配置直後Plantは既存rootDisplayUnitの出生投影を使用し、登録・吸水・時計進行はしない。Power/Speed/Range/Resist/Tech、土壌・在庫・水分・死体・天気・位置・HP等は変換対象にしていない。

実効Aura0は有限補正で表せない。根外端<=本体半径も正の到達距離へ完全変換できない。旧中心距離式のAuraは本体内の曲線も異なるため、この段階で自動変換しない。通常モードは根のBaseが存在しないため、root-v1のみの変換プレビューを提供する。これらを勝手に最小正値へ補正しない。

## 保存・バックアップ

プレビュー版geometry-migration-preview-1、status=preview-not-playable。旧root-save-1と異なる構造・checksumで、新/旧ローダーは相互に拒否する。旧root/normalの保存キー・ゲーム保存版は変更しない。

prepareGeometryDraftは旧保存のchecksum/由来/構造を検証後に投影。saveGeometryDraftは、元rawのhash別キーmorishi.geometry-migration.source.v1.root.<hash>へ同一バイトを保存し、読戻し一致を確認してから独立キーmorishi.geometry-migration.preview.v1へ書く。既存バックアップが異なる内容なら停止。バックアップ失敗・quota・元保存変更・変換不能値なら候補作成を停止。root/normalプレイ保存を上書きしない。ブラウザへの自動実行は未接続。

## 次段階の判断点

1. 新規生成を補正0付近にするか、現行seedの実効値を逆変換して継承するか。前者は本体半径50〜70から100へ、Auraおおむね10から200へ、根中心半径100から300へ変わり、大きな配置・吸水・接触バランス変更になる。
2. 成長は現行の実効値への加算を続けて結果を逆変換するか、補正への加算に変更するか。後者は倍率の導関数が異なり、栄養gain/水分消費の調整が必要。
3. 合体は現行の面積合成（本体・根）とAura実効値合算を維持して逆変換するか。補正値の直接合算は現行結果を保たない。
4. 実効0・本体内根・旧中心距離Auraの保存に旧モデル保持/特別な無効状態等を用意するか。移行を失敗停止する以外の自動方針は未決定。

Power/Speed/RangeのSkill Base値、Tech水分コスト、Aura正値のみ攻撃候補、無駄打ちの発動条件は今回決めない。現行の射程内条件を変更せず、新しい射程除外も追加しない。
