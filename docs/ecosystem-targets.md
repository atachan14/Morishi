# 存在感と標的選択の比較：2026-10-11

## 共有する判断

射程外の強い存在感へ標的が固定され、無攻撃になる不具合は確認されなかった。現行は射程内候補を先に絞り、毎tick選び直す。前衛が狙われにくい主因は、候補の存在感が全て0、または同じ最大値2のとき、距離に関係なく小さいIDを優先する仮仕様。先に生成された初期味方が、後から植えた前衛より優先される。

比較候補を一つだけ追加した。**存在感を優先し、完全同値なら距離、さらに同値ならID順**。標準の庭・保存済みの庭は元のID同値のまま。初期味方を守れる具体例はあるが、前衛がより強く攻撃される代価もある。万能な防御や遮蔽ではない。

## 混同しない三つの量

1. **存在感強度**：全個体共通の2。属性・防御・HPで増えない。
2. **存在感半径**：個体ごとの `直径/2 + 固有halo×sqrt(直径)`。haloは生成時の固有値。大身体と大haloは存在感の届く距離を広げるが、中心の強度2を増やさない。
3. **その場所で受ける存在感**：距離減衰した強度。半径内は2、半径〜2倍は `2×(2−距離/半径)`、2倍以遠は0。

`src/eco-sim.ts` の `targetCandidates/targetFor` は、攻撃者の中心で受ける**候補一体の存在感**を比較する。

`enemyPresence/validateEcoPlacement` は、置きたい芽の中心で受ける**敵全体の存在感の合計**が1.5以下かを見る。単一敵なら存在感半径の1.25倍以遠からこの条件を満たすが、複数敵なら合計で判定。標的の最大値選択とは別の処理。今回、この配置条件・強度・半径・減衰は変えていない。

## 選択順序と不具合調査

1. 生存する相手陣営だけを候補にする。
2. 中心間距離が攻撃者の実射程半径×2−0.000001未満の相手だけ残す。攻撃も中心間距離で減衰し、身体の端からの距離ではない。
3. 候補の距離減衰存在感を比較する。**射程外個体はここへ来ない**。
4. 従来は存在感同値ならID順。比較案は存在感同値なら近い順、距離も同じならID順。
5. 攻撃時計がたまっていれば、そのtickの選択へ攻撃する。毎tick再計算。`lastShot` は表示記録であり、ロック対象ではない。

攻撃射程と存在感半径は別なので、攻撃可能でも全候補の存在感が0になる。普通の初期配置で起きる。逆に複数の候補がそれぞれの存在感半径内にいれば、双方2で同値。どちらも旧ID順では「後から置いた前衛を避けて後ろの初期個体を狙う」ことがある。これは選択規則どおりで、射程外固定のバグ修正とは扱わない。

射程外の大身体（広い存在感）、死体、同陣営を混ぜたケース、全候補0・双方2・異なる正値・同じ距離、配列の並べ替え、次tickの再選択をテスト。新案でも**遠い候補の正の存在感が近い候補の0より大きければ遠い方を選ぶ**。最近傍だけを狙うルールではない。

## 通常生成の敵・合法な配置での実例

条件は射程×2・全属性25%継承・敵24体を初期全配置・自然成長と実直径吸収・手札入り時の基礎固定を維持。最初の手札3枚だけを使い追加補給なし。標的規則だけ変える。敵配置や生成能力の編集なし。

前後の点は最初の敵から `(-60,-45),(-120,-45),(-120,+45)`。実際の3seedと座標・能力・被弾先・各個体の攻撃は `evidence/ecosystem-targets/role-front.json`。集中／分散／前後／両側の4配置は `formations.json`。

### seed11：前衛が初期味方と後方射撃を残す

敵 #1 は (910.538635,646.142813)。前衛 #28 は (850.538635,601.142813)、後方 #29/#30 は (790.538635,601.142813)/(790.538635,691.142813)。初期味方 #25 は敵の左95。

4秒時点の敵 #1 の候補は、前衛 #28 が距離75・存在感0、初期味方 #25 が距離95・存在感0。旧ルールは#25、新案は#28。候補順位はUIの「標的を確認」でも同じ。

前衛カードは初期手札3枚のうち、固定基礎 `HP×(1+防御/70)` が最大のカード1（表示は芽#2）を選ぶ。残りは基礎耐久の降順で後方に配置。カード0（芽#1）は後方#30となり、属性→射程は電。耐久選択は初期値のみの簡易基準で、射程・速度まで最適化していない。

新案では前衛が実際に狙われ、初期味方はHPを保って10回攻撃、後方#30も独立して攻撃を続ける。同じ新案で前衛・後方のカード1と2を逆にすると、10秒の前衛HPは26.3、全体撃破は1体対2体。前に耐久を配置する具体的な意味が出た。

ただし近い前衛への攻撃は距離減衰が少ない。この配置の被ダメージ総計は旧164.8→新227.2。単に置くだけで得する守りではない。後方#30が攻撃できること自体は旧案でも同じで、今回新しく確認した差は前衛へ標的が移り、後ろの初期個体が守られること。

### seed77：耐久を見て選ぶ意味、後方射程の限界

同じ新案・同じ3点で、基礎耐久最大のカード2（芽#3）を前衛に置くと10秒時点の前衛HP64.5。逆配置では28.1。初期味方#25の被弾は旧77.9→新0となり、HP146.95を保って10回攻撃する。

後方#29/#30は攻撃するが、距離と固有射程のため10秒時点で1回・約0.05、3回・約2.21にとどまる。「後衛へ置けば十分な射撃役になる」とは限らない。射程も見て位置を決める必要がある。

### seed20261011：同値変更が効かない例

同じ前後配置では既に正の存在感の差が標的を決める場面があり、10秒時点の被弾先・攻撃結果は旧案と新案で同じ。前衛・後方のカードを入れ替えても差は小さい。前衛の存在感が後衛より勝つ条件や、敵の射程内に入ることが必要。同値調整だけで必ず守る訳ではない。

### 長く置いた場合と他の配置

自然成長で近い同陣営は合体し、独立した前後の役割は消える。前後間隔60は自然成長なら約17秒から接触し得る。対敵接触で成長が止まる場合もあるため、実際は状況次第。30秒・60秒の個体数と系譜も証跡に含めた。前衛が永続的に後衛を守るとは言わない。

新案の30秒撃破は、集中/分散/前後/両側の順に、seed11が3/3/5/5、77が3/3/4/4、20261011が3/3/4/5。全3seedで単一の配置が常に上回ることや、最適戦略不在は証明していない。全体攻略を速める調整が主目的ではなく、同値時の狙われ方を位置から予測できる調整。

## 朝の比較選択と保存

観察Paneの「新しい庭の比較設定」に選択は3つだけ：

- 全能力100%（従来）。既定のまま。
- 全能力25%（分散比較）。旧標的規則で吸収変更だけを見る。
- 全能力25%＋同じ存在感なら近い相手。今回の有力比較候補。

速度・射程を継承しないguard案は前回比較で進行を止めやすかったので、UIの選択肢から外した。保存済みguardの計算・再開は維持。選択を増やすための独立した標的ドロップダウンは追加していない。射程×2の同seedで25%案同士を比較すると、今回の差を切り分けられる。

`targetPolicy:'presence-nearest-v1'` を新しい比較runと個体に記録。未指定の旧保存はID同値のまま。吸収後も受け手の規則が維持され、配置した新個体と配置プレビューにも同じ規則を渡す。未知の規則・state/unit混在を保存読込で拒否。旧runのrawは明示的新runの前に退避し、退避失敗時の上書き防止も維持。

個体詳細の「標的を確認」は初期状態で閉じる。開けば上位3候補の現在の存在感・距離と選択順を見られる。候補順位は実際の `targetCandidates` を共用。数値は表示で丸めるが、選択は丸める前の完全同値を使う。極小差を同値扱いする任意epsilonやランダムは加えていない。
