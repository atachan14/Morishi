# 配置を続ける試遊と再開

## 今回の判断

数値・保存の技術的な破綻は確認されなかった。次は、手札の属性と役割を見て置き場所を選ぶ遊びを確かめるため、候補地点の現在の攻撃・被弾を読めるようにした。戦闘ルールや比較設定は増やしていない。成熟した敵の近くで新しい芽が倒され、攻撃が長く止まる問題は遊びの課題として残る。

## 実際に配置を続けた検証

最初の240秒は既存個体への接触配置。その後、発射が10秒以上途切れたときは生きた敵の近くへ新しい前線を置く。240〜360秒は前線拡張、360秒以降は三回に一回を接触配置とした。条件名は初期配置の違いであり、全時間ずっと集中・分散を強制するものではない。

180回の定期保存と525回の配置直後保存を検証。6条件の最終状態は完全一致。配置直後を含め最大30個体、保存最大27814 bytes、ログは8件以内、最終発射記録は2〜4件。HP・直径・能力・供給時計は有限値と上限を保った。最終状態は全条件まだプレイ中。

これは「10分間ずっと戦闘が続いた」という結果ではない。両陣営を数えた発射なしの最長区間は82〜185.2ゲーム秒。後半の新しい芽が成熟した敵に倒される状況もある。成長が起きたtickは733〜958、発射が起きたtickは266〜685 / 6000。勝利への回復経路や待ち時間の面白さは未確定。

記録の cpuMs は performance.now によるスクリプト経過時間で、実CPU使用時間ではない。5チャンク実行は約2.496 / 1.193 / 1.212 / 1.422 / 7.511秒（最後は最終再生を含む）、配置ごとの独立再生は約7.905秒。ゲーム内時間とは別。

証跡: `evidence/ecosystem-active/*.json`、`placement-replay.json`。再現スクリプトは `scripts/ecosystem-active-chunks.mjs` と `ecosystem-active-replay.mjs`。

## 同じ地点から試す

敵・観察の「試遊の再開」で「この地点を残す」を押すと手動の一点を保存する。自動保存や新規開始では更新しない。「同じ条件で最初から」は現在のseed・射程・合体・標的条件・供給時計設定・速度を引き継ぎ、進行と獲得分を初期化する。「残した地点に戻る」は盤面・手札・視点・速度を復元し、停止状態で再開する。

手動保存は `morishi.ecosystem.checkpoint.v1`。通常保存と前run保存とは独立。復元時の現在runは前runキーに退避するので、試行分岐を捨てる前の生データも残る。手動保存は一枠で、再度明示保存すると更新する。容量不足・未知形式・退避失敗では既存生データを保護する。履歴一覧や複数スロットはない。

## 置けない理由と候補の読み方

配置失敗後だけ開ける詳細に、tick・座標・実際の拒否理由・接触個体IDと必要距離・敵の存在感の寄与を表示する。接触と存在感の合計による制限は別の検査。表示は観察だけで、手札やチャージを消費しない。

手札から合法な候補を探した後、「この候補での攻撃・被弾」で現在の標的・一発の与ダメージ・HP・射程を見られる。その地点の芽を標的にする敵について、一発の被ダメージと攻撃速度を上位三体まで表示する。現在のスナップショットでの値であり、次tickの合体・同時攻撃や今後の生存を保証しない。直径200での射程は「接触せず生き残る」条件を明記した。

## 検証範囲

144テスト、TypeScript/Viteビルド。Edge154のPC 1366×768とスマホ相当390×844で保存・同条件リトライ・厳密な停止復元・失敗時非消費・候補表示と計算の一致・容量不足・未知保存保護を確認。実行時エラーなし。証跡は `evidence/ecosystem-trial/browser/`。

高密度128個体と巨大個体の描画測定は各約2秒の停止中人工配置。実戦操作のブラウザ確認も短時間であり、実時間10分や24時間の連続稼働を証明しない。実機スマホ・高密度で戦闘を続ける実時間試験は未確認。公開・push・スキルカード作成は行っていない。

後続の [成熟敵への立て直し](ecosystem-recovery.md) では味方だけの発射も集計した。両陣営の発射が続くことだけでは味方が戦えているとは言えず、185秒には最初240秒の固定配置方針も影響している。
