# v2 応答を保つ時間送り

既存の送り100×speed ticksを、完了したモデルtickの間で分割する。1回の作業は目標12ms・上限8ticks、その後ブラウザに制御を返す。ゲームのdt、RNG、tick順、800tick上限、最後の味方喪失/既存outcomeでの停止は変更しない。

送り中は通常再生を一時停止し、既存の再生ボタンを「停止」として使う。Pane移動と保存も使える。配置・新規生成・速度/環境変更などは通常操作で無効化する。完了後は元の再生状態へ戻すが、キャンセル・非表示・味方喪失時は停止を維持する。

停止や保存は完了したtickのprefixを保存し、その後の古いPromiseが再開しても仕事をしない。新規run・保存モード復元・予報開始は古い仕事を取り消す。予報では入場時点の実ゲームを固定し、その後の保存キーも固定。状態所有者とjob identityを確認して、古い仕事が新しいrunに保存・unlock・再生を行わない。

## 検証

同期処理と分割処理の全4速度で、全ゲーム状態とcompact saveが厳密一致。キャンセル後のprefix・保存復元・所有者変更・時間予算・既存停止条件・不正入力を6testsで検証。区間診断の非干渉を4testsで検証。全309tests成功。

隔離headless Edgeの1366×900、390×844、320×568で、3日成長後の同じ保存点を使った。800ticksの完了まで約2.87～2.94秒で、約206～209回の12msheartbeatが実行され、最大応答間隔約29.7～32.5ms。従来の同期2.09秒に対し全体の時間は少し長いが、操作を2秒固めない。1tick自体が重い極端なrunの応答時間は未検証。

ネイティブの停止/保存操作、再読込後の停止復元、実際の別タブ切替による非表示キャンセル、再生中送りの元の再生への復帰を3サイズで確認。新規run・normal復元・予報への直接ハンドラー切替でも古い処理が残らず、partial/final saveは同期処理の同じtick数と厳密一致。元のnormal saveは不変。実行時エラー0。既存のroot保存QAも3サイズで通り、破損保護・2MB/容量制限時の旧保存保持・backup復旧・戦闘/死体/配置合体後の復元一致を確認。独立予報の回帰も3サイズで状態・全保存キー不変。実機スマホではなくWindows Edgeのviewport/touchエミュレーション。

最初のQA比較はJSON転送でundefinedが省かれることを考慮せず失敗した。保存JSONへ正規化して厳密比較するよう検証コードを直した。serialization-check-first-attempt.jsonは検証コードの失敗で、ゲームの状態差ではない。

証跡: evidence/ecosystem-v2-chunked/browser/browser-check.json、3画面、tests.txt。scripts/ecosystem-v2-chunked-check.mjsで再現。既存画面QAのforwardクリックはaria-busy解除まで待機するよう更新した。runtime-observeの送り測定もPromise完了を待つ。

モデルや既存のbalance値に変更はない。実時間の長期プレイ、人間の操作感/面白さ、実機、通常再生8倍の極端な高負荷時は未確認。
既存QAの待機を最初に広く文字置換したためスクラブ関数にもsel参照が入り、検証コードが失敗した。ASTでクリック関数のみに限定して修正し、予報/保存QAを再実行して成功。click-wait-first-attempt.jsonはこの検証コードの失敗記録。
