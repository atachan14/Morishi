# v2根モードの新形式保存・再開

天候基盤の接続状況は [v2天候基盤](ecosystem-v2-weather.md) を参照。予報操作UIは次段階。

対象: http://localhost:8781/ecosystem-v2.html 。基準HEAD `9dcc301` の根合体・死亡栄養を保持。天候本体は追加しない。

## 保存と再開

根保存versionは `element-root-save-1`、専用キーは `morishi.element-root.v1`、置換前原本のキーは `morishi.element-root.previous.v1`。通常保存 `morishi.element-skills.v1` と通常のreader/移行/バックアップは別で、根操作から書き換えない。旧readerの根run拒否も残す。

Settingに「保存」「保存を再試行」「根の保存へ」「通常の保存へ」を追加した。初回または最後に選んだモードの保存を読む。再読込・切替は必ず停止状態で、時間の追い付きや過去の弾の再生をしない。根がない旧通常saveも従来のreaderで開く。通常runで通常保存を行う操作は従来の通常保存・移行動作を使う。

新旧切替はまず移動先を読んで検証し、現在の保存が成功してから切り替える。移動先が壊れていたり現在の保存が失敗したりすれば現在の庭を保つ。根runから新しいrunを作る時も、可能なら現rootを先に保存し、置換前rawをバックアップする。破損rawは自動上書きしない。読込後に別の操作で破損されたrawも検出して原本を保護する。明示的な新runだけがバックアップを作って置き換える。

失敗時は進行を停止し、現在の庭と以前の正常saveを維持して失敗表示と再試行ボタンを出す。再試行は保存だけで、新tick・配置・消費を増やさない。保存可能な内容へ直るまでデータを削ってサイズ制限を回避することはしない。

## 保存内容と同じ操作の再現

Unitの実効root Stats・HP・サイズ・個体容量・Skill時計・系譜・敵由来、RootPlantの水/mix/未消費bonus、土壌の動的水/bonus、有限死体の位置/直径/在庫/回収枠、死体投入/消費/退役帳簿、生成seed/設定/確定手札/撃破報酬、tick/root経過時刻/昼夜phase、viewを保存する。死体25%の仮規則もruntime設定として保持する。

配置直後、最初の根tick前の個体は保留状態のまま保存し、captureで根を初期化したり資源を使ったりしない。保留個体はborn=current tick・age0・単体系譜・初期直径等を検査。通常個体はUnitとRootPlantのStats/HP/サイズ/位置/水/容量が一致することを検査する。mix総量と水、有限vector、死体と生存由来の分離、Skill/seed/報酬/カードの整合性も確認する。

JSONで省略されるundefinedは同じ意味として正規化比較する。復元後の同じstep/配置/合体/吸水の結果は完全一致を照合する。捕捉中のリアルタイムaccumulatorは保存せず、復帰は停止して端数の外部実時間を再投入しない。

## 固定土壌とサイズ制限

20成分×各セル16サンプルの固定profilesをそのままJSONへ入れると、100体・半径2400で全状態約8.12MB、半径4000で約20.14MBになる。固定配分は `root-profile-1` recipe（格子と明示的patches）から再生成し、動的な水配列と非ゼロ土壌bonusだけを保存する。runSeedも照合する。

captureでは現profilesとrecipeの厳密一致を検査する。再生成した配分のfingerprintも保存し、読込時に一致しなければ保護して失敗する。同じ生成versionの計算を後から変えない。未知の配分を推測して再生成しない。静的配分は凍結し、動的在庫は共有せずコピーする。blueprintは一形状だけキャッシュし、通常保存で毎回土壌を生成し直さない。

保存上限は **UTF-8で2,000,000 bytes**。読み書きとも検査。再生成の安全予算は最大4096セルで、現行の根半径4000の2916セルを包含する。通常モードの半径100000の範囲は変更しない。大量の未回収死体/大きい系譜で上限を超えた場合も、以前の正常saveと現ゲームを維持して失敗する。
