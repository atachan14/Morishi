# 長時間runの保存

2026-10-11。開始HEAD: c5837d2abbaac0a60a2ec550726b2b078191c211。

## 修正前の問題

旧版の上限はゲーム内60分（36000tick）。超過してもプレイは続くが、writeがfalseになり、保存は最後の成功時点に留まる。実測で36001tickのwrite=false、再読込で36000tickへの復帰を確認した。失敗表示は右Pane下部だった。長いrunの保存としては不十分だった。

## 現在の保存

毎回の保存は、現在の全盤面を正確に複製するスナップショット。tick、seed、HP、能力、年齢、攻撃クールダウン、target、lastShot、手札、領域、配置力、結果、イベントを復元する。成功配置/終了の操作ログも保持するが、読込時に経過tick全体を再生しない。この試作は初期敵7体と有限の芽18体なので、スナップショットと操作ログのサイズは経過時間に比例して増えない。

60分の時間上限は撤廃。tickは非負の安全な整数、読込は64KB以内、ユニット/領域は最大25、操作は最大19とする。保存versionは `2026-10-11-snapshot-2`。JSON破損を検出するchecksumに加え、seedから生成される能力・位置、配置ログから導けるID・年齢・手札、HP/クールダウン/領域/結果等の整合性を検証する。checksumは改竄防止や認証を目的としない。保存由来のイベントはHTMLとして解釈せず、エスケープして表示する。

旧 `2026-10-11-runtime-1` の保存は最大36000tickのログを一度だけ再生して移行できる。新方式で最初に保存する前に旧rawを `morishi.run.previous.v1` へ退避する。退避に失敗した場合は元保存を変更しない。新run開始時も同様に前保存を退避する。破損/非対応保存は自動上書きしない。

## 保存失敗と復帰

配置・1Tick・速度変更・終了・画面離脱、進行10tickごとに保存。保存の拒否・容量不足等では停止し、全Paneから見えるヘッダー直下へ警告を出す。画面内の現在状態は残すが、再読込で最後の保存へ戻ることを明記する。時間を進めるボタンで再保存を試し、成功するまで進行・配置を再開しない。画面離脱時も再試行する。毎frameの無限再試行はしない。

読込後は停止状態。ゲーム速度は復元するが、部分tickと背景時間を持ち越さない。タブ非表示/blur/pagehideで停止、復帰最初のframeを捨て、明示的な再開を待つ。既存の入力安定化は維持。

## 検証

- 46自動テスト成功。旧上限の前後で最新保存を復元、4倍速で復帰後の10tickを正確に進めること、停止中の600000msを捨てることを確認。
- 旧版移行とraw退避、移行退避失敗時の旧保存維持と再試行、上限超過時点のquota失敗で直前保存が残ること、破損checksum/不整合スナップショット/別versionの拒否を確認。
- 非常に大きなtick（10億）の構造上有効な状態も履歴再生なしで復元。これは長時間を実際にプレイした証拠とは分ける。
- `node scripts/long-run-save.mjs`（先にnpm test）: 4倍速で24ゲーム時間・864000tickを加速シミュレーション。88回の保存復元で全状態一致、背景catch-upなし。保存最大3065bytes、復元最大1.343ms。盤面はseed11・味方1体の8体盤面で、端末性能の保証ではない。証拠JSONは evidence/long-run-save.json。
- TypeScript型検査・Vite本番ビルド成功。既知のPhaser込み500KB超chunk警告は残る。
- ブラウザ操作ツールの初期化エラーが継続しており、実ブラウザのlocalStorage・タブ操作・スマホ表示は未確認。加速ロジック検証は24時間のブラウザ連続稼働検証ではない。

origin単位の端末保存であり、host/port変更、端末側の保存削除、private browsing等の保持方針には依存する。クラウド同期や外部公開、pushは行っていない。
