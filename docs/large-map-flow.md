# 比較盤面の操作確認

2026-10-11。36×27・敵24体の比較盤面は引き続き仮の検証サイズです。ルール・数値バランスは変更していません。

再現した不具合は、一覧から遠い敵を選ぶと情報だけが更新され、盤面には対象が見えないことでした。画面外の対象を選んだ場合に、現在のズームを保って対象へ移動するよう修正。既に見えている対象では移動しません。選択時に現在のstateから座標を取得するので、seed変更後にも同じIDの古い座標を使いません。味方の射程確認ボタンにも同じ処理を適用しています。

隔離したEdge154で、seed 20261011 / 11、PC1366×768 / touch設定390×844の4runを実際のUIから開始しました。敵6付近への配置、敵・味方情報、4倍速の進行中に敵19へ移動、停止、変化まで時間送り、ズーム・ドラッグ、別敵群への2回目の配置と時間送りを確認。意図しない追加配置はなく、停止中のtick維持、全生存個体の経過tickとの一致、実行時エラー0を確認しました。画像は縦長画面のseed11で敵19を選択した状態です。

進行中に最初の戦闘を画面外へ移しても、最初の敵のHPは20261011で0、11で約13.062まで進行しました。描画対象から外れても戦闘が続いています。別途、前回の画面外fixture検証は `docs/entry-tail.md` に記録しています。

4runの短い操作中、requestAnimationFrame間隔は95%点で約16.8ms、最大17.2ms。50ms超の間隔とPerformanceObserverのlongtaskは0でした。今回の規模・少数配置では追加最適化を必要とする停止を測定していないため、性能変更は加えていません。時間送りの観測時間は約94〜106msですが、操作スクリプトの待機とCDP通信を含むため、シミュレーションの計算時間ではありません。

これは同一PCのheadlessブラウザでの短時間確認です。実機スマホ・Safari、全攻略までの長時間プレイ、多数の味方が残る状態の性能を保証する測定ではありません。80単体テストとproduction buildは通過。既存のPhaser chunkサイズ警告のみです。

証拠は `docs/evidence/flow/browser-check.json` と画像、再実行は `node scripts/flow-browser-check.mjs OUTPUT_DIRECTORY`。初回の不具合再現はPCで確認しました（初回の縦長画面スクリプトは非表示canvasの矩形取得で停止したため、修正前の縦長画面の再現証拠とは扱いません）。
