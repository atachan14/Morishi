## 現行の数値・実処理の対応

Plant詳細のPower/Resist/Range/Speed、HP/Max/HPReg、存在感はcurrentV2Statsと同じ実効値。rootモードは初期実効値を保存し、その後は水を使った直接増分。成長した直径でStatsを再倍率適用しない。通常モードはpercent-1のサイズ倍率を使う。

新規の基準直径100%に対し、敵の活動属性射程14～22、手札9～16、存在感7.5～12。敵は初期直径100/120/140%なので、初期実効射程と存在感はそのサイズ倍率を反映した値。rootへの初期接続はその実効値を保持する。いずれも仮の生成基準で、旧保存を再抽選しない。敵と手札の射程差を変えるのはバランス/生成仕様の別提案。

攻撃/治癒は双方の身体表面間距離d=max(0,中心距離−両半径)。距離係数max(0,1−d/R)、境界Rは0で候補から除外。攻撃は同属性防御で軽減し、rootではPower/(1+Resist/100)、通常は分母70。治癒はPower/2を範囲内の傷ついた同陣営へ。SpeedはSkillの準備回数/秒。Powerそのものが常にHPへ入る値ではない。

存在感は身体外からS−距離（傾き1）、配置は候補身体の半径を含めて全敵の正値合計0かつ身体非重複。根の範囲や射程は配置可否の代用ではない。「合法」と「敵の攻撃が届かない」も同義ではない。これらは既存規則で、今回は変更しない。

## 操作・予報の照合

中央下手札→個体詳細→配置確認→Mainで位置をタップ、取消、味方/敵の選択と3Pane切替は接続済み。touch/Pointerで配置し、手札クリックが盤面へ落ちない既存ガードもある。今回のPC/SP実操作で手札選択→確認→停止配置→味方詳細を確認。配置後に勝手に詳細Paneへ飛ばす仕様変更はしない。

予報と実際の雨は同じweatherAt/rainAtとseed/tickを使う。予報カーソルの雨位置・強度は対応する実時間tickと一致する設計で、天気/予報のモデルテストと回帰QA済み。予報は独立時計で実ゲームを変更しない。

予報バーは8×8の全域潜在雨量、実受入雨は土壌4×4サンプルと空き容量、植物吸水はさらに根の共有/容量の制限を受ける。したがってバーの高さと実際の貯水増加は同じ数値ではない。水の色、根の円、死体の円も現在別の表示で、場を塗り替えるような大きな視覚仕様は未採用。

## 今回修正した出生表示

rootDisplayUnitは実登録と同じplant initializerを使う読取専用表示。rootDataがまだない手札/保留配置だけに、根100、水0/現在runの容量、吸水0を表示。既に登録済みの個体は元の実データと合体容量をそのまま使う。通常モードは変更しない。

まだRootPlantへ登録されていない保留配置はそのまま保存し、描画で登録や吸水を実行しない。最初の根tickで従来どおり登録する。canvasの診断にはpendingRootを記録して表示投影と実登録を区別する。

固有3testsで元Unit/元素値/保存/土壌の不変、night最初の実登録との初期Stats一致、通常/合体容量保持を検証。全312tests、型検査、本体/root-trial buildを確認。隔離Edge1366×900、390×844、320×568で手札・停止配置直後・水overlay・保留保存復元・旧normal保存不変を確認。実機スマホではない。証跡はevidence/ecosystem-v2-root-display、scripts/ecosystem-v2-root-display-check.mjs。
