# 朝の試遊版：境界条件と実時間検証

戦闘・生成・保存形式・待機ルールは変更しない。新配置と既存の3比較条件を維持し、全体安全探索の診断を自動候補へ追加していない。手札・能力対応・育成強化の表示を検証し、攻撃間隔だけ実際の時計に合わせた。

## 横断検証

`tests/eco-cross-boundary.test.ts` で以下を確認。人工的な接触・瀕死盤面は境界条件用であり、通常プレイ経路の証明とは区別する。保存検証は生成した固定seedを保持し、敵由来24個を損失/重複なく追跡する。

- 64seed×3吸収方針で24通りすべての1対1属性対応を通過。異なる対応の個体を連続合体しても、受け手の固定対応と、表示属性・攻撃・防御・時計速度・射程が独立計算に一致。
- 炎などの同じ属性量を継承し、受け手の対応で能力へ変換する。被吸収個体で射程に対応していた炎が、受け手では攻撃になることがある。身体増加による基礎成長と吸収ボーナスを別に加え、固定seedへ報酬倍率を再適用しない。
- すでに合体した個体を吸収する場合、その個体の現在属性（過去の吸収分を含む）を1回だけ転送。25%吸収では合体段階ごとに25%を適用するため、以前の吸収分も次の転送で減率される。これを重複適用と取り違えない。接触が解消した後の再実行では追加ボーナスなし。
- 同tickの処理順は成長/HP容量増加・回復→接触合体→生存者の攻撃記録→全ダメージ→死亡・撃破報酬→（勝利でなければ）ドローと配置力時計。致死攻撃は双方が同tickに発射でき、死亡後は除去され、次tickの回復で復活しない。吸収済み個体は同tickに別の攻撃をしない。
- 同tickの複数撃破はすべて新しいドロー札の確定値へ反映。一方で保持札・配置済みの固定基礎値は変わらない。後から保持札を配置/吸収しても再強化しない。
- 合体した敵の由来が複数でも、撃破報酬は倒した1個体につき主属性+0.01を1回。全24由来を合体した最後の敵を撃破した場合も1回。最後の撃破では勝利がドローより先に確定するため、そのtickで新札は追加されない。復元した勝利状態は進行しない。
- 各境界で厳格な保存読込に通り、再開後の状態一致と由来の一意性を確認。

## 攻撃速度の表示補正

既存の攻撃時計は0.1秒刻みで、準備量を1に制限し、発射時の超過分を保持しない。したがって内部時計速度4でも定常的な連続攻撃は0.3秒間隔（約3.33回/秒）。戦闘時計を修正して既存runの結果を変えることはしていない。

個体・芽→直径200・条件付き合体比較は、内部時計速度を発射回数として出す代わりに、現在の能力が固定され射程内に相手がいる場合の攻撃間隔を表示。候補の被弾表も間隔（秒）とし、秒当たり被弾の目安はこの定常間隔で算出。攻撃準備量・標的・成長・合体で実際の初弾/以後の結果は変わる。生存時間や安全性を保証しない。

5種類の時計速度で実際の発射tick間隔を測り、表示関数に一致することを検証した。

## 実時間とブラウザ復帰

`scripts/ecosystem-realtime-browser-check.mjs` は隔離した既存Edgeだけを使用し、ユーザーのブラウザには触れない。オフライン経過時間をシミュレーションへ足さない。

最初の回復過多の人工盤面は、成長が止まった後に約64ゲーム秒で自然停止した。この失敗記録は `evidence/ecosystem-boundary/realtime/` に保持。アプリの停止ルールを変更する代わりに、継続戦闘がある人工診断盤面へ回復量を調整した。人工盤面の耐久ボーナスは安定性測定用で、通常生成のバランスではない。

修正した診断条件の記録は `realtime-balanced/`。PC1366×768では1倍速で実時間300秒、スマホ幅390×844では30秒の連続稼働を測る。15秒ごとの自動保存を厳格読込し、同じtick数の独立シミュレーションと状態比較する。さらに手動停止で保存不変、再開、別タブによるブラウザの本物のtrusted非表示イベント、表示復帰時の停止維持、手動再開、再読込の正確な停止復元を検証する。非表示属性を偽装しない。

自然な配置記録から再現したseed103の120ゲーム秒地点も、各画面で実時間約10秒動かして保存の状態一致を確認。これは人工盤面の5分測定とは別の短い確認。

この有限測定は24時間稼働・あらゆる環境・長期メモリ安全の証明ではない。長い待ち時間や人の試遊による理解しやすさは引き続き評価対象。

全164テスト・TypeScript/Viteビルド成功。実時間/画面検証の成否は `evidence/ecosystem-boundary/realtime-balanced/realtime-check.json` と `browser/browser-check.json` を参照。

最終結果：修正条件のPC/スマホとも実時間検証の失敗0・実行時エラー0。PC300秒で3000tick、スマホ30秒で300tick。非表示は別タブの実際のイベントで確認でき、ライフサイクル凍結へのフォールバックは使っていない。途中保存最大はPC27924 bytes、スマホ27941 bytes。自然盤面は両画面とも1200→1302tickで状態一致。終了後GC時点のJS heapは約1.76 MB/1.69 MBという参考値で、長期リークがないという証明には使わない。
