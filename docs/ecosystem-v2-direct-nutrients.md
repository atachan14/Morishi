# 純水・土壌/遺骸からの直接有限栄養取得

最新要件: ユーザー1791943143.665879。遺骸取得でも実取得量に応じ水を払う追加1791943568.257189。名称は土壌（初期栄養）、遺骸（死後エリア）、両者を栄養。旧案の「Skill使用水にmix/bonusを比例消費」は撤回・未採用。この文書を現在の栄養処理の入口とする。過去文書の永久profile供給・水中栄養保管は旧保存モデルの記録。

## 接続した構成

既存の広域有限Soil、支持減衰、4×4サンプル、局所所有者集合、雨、水在庫、根円、接触停止、遺骸生成、日光、戦闘、0基準幾何投影を再利用。ゲーム全体を別版として作り直していない。新規root runにdirect-finite-1を付与し、旧runは旧モデルを保持する。

1. 雨を空き土壌水容量まで受入れ、根の局所共有サンプルから純水を吸収する。水は栄養を保持しない。
2. Skillを固定順で処理する。属性順は炎→氷→電→闇、同属性はskill.key順。各Unitの水で支払えるものだけ発動し、不足するSkillは飛ばして後続を確認する。BaseCost=1水、Cost=1/M(Tech)。攻撃/治癒とも1発分のCostで、治癒の対象数では追加請求しない。射程外効果0・負Aura対象も発動分を払う。
3. 不足時は準備1を保持する。足りたtickに1発、待機期間の連射負債は蓄積しない。通常のSpeedによる複数発動でも、実支払済み回数だけ効果を出す。
4. Skill後の生存Unit・残水・現在根範囲から、土壌と遺骸の取得要求を同じsnapshotで作る。日光0/残水0/接触による成長許可0なら要求0。
5. 土壌と遺骸の要求を合計し、残水と成長許可水量の小さい方に合わせて同じ縮小率を掛ける。その後、各source・栄養種の在庫不足を全Unitへ比例縮小する。再配分ループで順番優位を作らない。
6. 在庫減少・全Unit取得・実取得量に比例する水消費・能力増分を一括反映する。取れなかった分は水を払わない。遺骸も同じ共通残水から支払い、同じ水を二重使用しない。

戦闘の同tick効果収集/回復/ダメージ/死亡処理を既存方式で維持。新モデルではSkillの解決を成長前へ置き、死亡個体は成長しない。Skillで生じた遺骸はその後の成長phaseの有限sourceとなる。根成長後の接触合体は既存処理を維持する。

## 局所性・保存則・順序

土壌のconeサンプル密度を残し、同じセルの別地点の栄養は根内にあるものとして扱わない。各sourceの現在密度は残量/初期量で更新する。重みは接触面積×現在密度、局所shareは1/n。土壌の接触範囲内の現在在庫量も、そのtickの上限とする。根内に栄養サンプルがない場合は取得/成長水消費0。

要求をUnit/source/重みの安定順で集計し、source・栄養種ごとに足りない分を比例縮小。純粋関数は入力を変更しない。在庫減少=全Unit実取得、成長消費水=全実取得×換算係数。水不足では土壌/遺骸の両要求へ先に共通係数を掛けるので、どちらを先に計算したかで結果が変わらない。

遺骸は土壌とは独立の円を格子サンプルし、重なりの局所1/nを使う。土壌外の遺骸も対象となる。通常の格子間隔は土壌のsubsample間隔、大きな遺骸では半径/70以上としてサンプル数を抑える。積分/境界は数値近似で、巨大遺骸や終盤の実機性能は別途確認が必要。

新runはelement-root-save-3、密度演算versionはcone-samples-1。静的密度は明示recipeから再現し、変化したセルの現在栄養だけ保存する。種別の初期量=現在在庫+土壌実取得の帳簿を検証し、未知version・非有限値・在庫作成/消失を拒否する。
