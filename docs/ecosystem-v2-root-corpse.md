# v2死亡栄養の最小接続

確認URL: http://localhost:8781/ecosystem-v2.html 。Settingの「根成長を試す（保存なし）」をONにして新規作成。基準HEAD `8314415` の根合体を保持し、死亡栄養を接続した。保存・天候は追加しない。

## 仮規則と単位

本接続は仮値であり、面白さや最終バランスの確定ではない。`src/eco-root-trial.ts` の `ROOT_CORPSE_DEFAULTS` で次を分離した。

|項目|仮値|意味|
|---|---:|---|
|diameterFactor|4|死体エリアの**直径**＝死亡時の実身体直径×4。半径は身体直径×2。身体直径100ならエリア直径400・半径200|
|statFraction|0.25|死亡時の4属性×Power/Range/Speed/Resistの実効値25%を新しい回収可能量にする|
|recoveryWaterPerDiameter|0.25|全量回収に必要なエリア内の累積実吸水量。身体直径100なら25水。この値は回収の割当枠で、死体の貯水や新しい水在庫ではない|

範囲・回収枠は死亡ごとに固定し、配置座標を丸めない。円と根の重なりは既存の土壌小サンプルで近似する。係数の変更は新しい死亡から適用できる。

死体に実効Statsをそのまま入れて、成長時のgainsをさらに掛けることはしない。新規栄養は成分ごとに `死亡時実効Stat × 25% / gain` の**栄養単位**へ変換し、既存のRootPlant.bonusへ移す。消費時にgainを一度掛けるため、全量を消費した成長増分は死亡時実効Statの25%に一致する。例: Power40、gain0.2なら50栄養を投入し、全消費でPower+10。通常runのgainsはこの区切りでは固定。gain0の成分は新しい回収可能量を作らない。

不明な返還範囲を広げない最小案として、MaxHP・現在HP・HPReg・根・存在感・身体サイズ・容量を新しい死体栄養にはしない。死亡時の貯水は従来どおりretiredWaterへ移して水収支に残し、土壌へ水を追加しない。一方、**既に吸った未消費bonusは全成分をそのまま死体へ移す**。再び25%を掛けたりgainsを二重適用したりしない。これは既存の有限在庫の移動であり、HPReg等の新しい返還規則ではない。

## 処理と保存則

戦闘の同tick効果を集計してHPを確定し、実死亡ごとに一回だけ栄養を置く。RootPlantを同時に除去するため、二回目のretire呼出しは無操作で、死亡個体は次tickの吸水・成長に参加しない。合体はこの入口を通らず、死体・投入数・死亡報酬を増やさない。

土壌の初期配分profilesは変更しない。死体在庫は通常の水mixと別の有限vector。各エリア内で実際に吸った水を、同じ小領域の実吸水割当に応じて分配し、一つの在庫を一度だけ減らす。満水の根や水を吸えない根は回収しない。複数エリアが重なるとそれぞれの在庫を載せられるが、各在庫は有限で二重回収しない。

回収枠を吸い尽くすとエリアは消える。回収済みの未消費bonusは植物の貯水側に残り、日照と成長許可がある時に水と同じ比率でStatsへ加算する。根合体では既存のbonus加算で移り、後に植物が死亡すれば残りを次の死体へ返す。`corpseAdded` は新規の死体由来栄養だけを成分別に記録し、戻した既存在庫を新規投入として二重計上しない。

既存の敵撃破による手札強化・報酬・保持カードの確定値を維持する。死亡栄養とカード強化を**併用**するため、累積強化・敵も栄養を拾う効果・25%係数の面白さは次のバランス課題。勝利後は従来どおり進行が停止し、最後の敵の死体も追加で自動回収しない。
