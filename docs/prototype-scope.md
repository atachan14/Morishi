# Morishi 初回ローカル試作

日付: 2026-10-11

## 残す核

スマホで遊び続けられる一人用。囲碁的な「陣地を広げる感覚」を最優先し、配置の相互作用を続く柱にする。少ないルールの深さは必須にしない。ライト層でも浅く楽しめる入口を作る。

旧Unity版 `G:\source\repos\unity\Morishi` は保全する。原文は `docs/restart/2026-10-11-first-concept.md` にコピーし、ここでの仮仕様とは区別する。

## 初回範囲と仮決め

- Phaser + TypeScript + Vite。表示と純TSシミュレーションを分離。
- 12×9ワールド単位の連続座標の小盤面。敵7体を全て初期配置し、能力を公開。
- 配置→進行/停止→自律攻撃→敵攻略→領域拡大を確認する。
- seedで能力を生成し、以降は乱数を使用しない。固定100ms tick、安定ID、同時ダメージ適用。射程内の存在感/距離スコアで標的を選び、同点は小さいID優先。
- 種族定義なし。4能力への生成時配分から個体差を作り、現在の能力配分から形・色を決める。年齢による成長は見た目・射程・攻撃・存在感に反映。属性は未実装。
- 左端2ワールド単位は初期領域。味方の成長と敵攻略で領域を増やし、一度得た領域は保持する。
- 仮の供給は生成済み18体。次の3体を公開。配置力は初期3、進行8秒ごと/敵攻略で+1、最大5。敵の種継承・複雑なDeck育成なし。供給は独立した仮ルールとして差し替え可能。
- 勝利は敵全滅。敗北は味方全滅かつ残りの芽なし。再挑戦可能。
- PCは配置/味方・盤面・敵/観察の3Pane、760px以下は1Pane切替。タップ/視認/切替の短い初期確認を行い、全面スマホ調整は後続。
- 合体、変態、属性反応、保存、長期進行、外部公開は今回の範囲外。

## 操作とテスト

1. `npm install`、`npm test`、`npm run build`。
2. `npm run dev`。`http://127.0.0.1:8781` のみで待受け、既存8771/8774/8780を避ける。
3. 左の明るい領域をクリック/タップして配置。植物クリックで射程と能力を見る。
4. 時間を進め、停止、1 Tick、1/2/4倍速を試す。新領域に配置して敵の減少を確認。
5. PCで3Pane、狭い画面でPane切替・タップ・視認性・横はみ出しを確認。
6. 同seed再開、別seed、無効seed、不正配置、供給不足、終局を確認。

自動テストは同seed入力の一致、フレーム分割/速度の一致、停止整合、不正配置非破壊、HP/供給の範囲、標的、勝敗後停止を確認する。実機スマホの継続プレイ品質やゲーム全体の面白さ、24時間無停止開発を保証するものではない。

## 同日更新: 連続座標・自由配置

ユーザーが旧Morishiのようなアナログな配置をほぼ必須の前提と明示。マス配置を廃止し、スナップ・整数化・丸めなしで入力のワールド座標を保持する。初回原文記録の既存本文は保存したまま、同日の補足節を追記した。旧Unity版の原文は変更しない。

- 盤面は12×9の連続ワールド座標。幅・高さは空間単位で、マス数ではない。
- 植物の当たり判定は円。配置時半径0.3、成長に応じて最大0.378。見た目の外周リングと衝突円を一致させる。
- 配置時は有限値、円全体が盤面内、全植物との非重複、自領域の中心位置、配置資源を判定。接する円は配置可。epsilon=1e-9で微小な計算誤差を吸収する。成長後の味方同士の接触/合体は未実装。
- 明るい自領域は初期帯と植物/攻略による円の集合。敵の半径1.15の領域を除外。成長・攻略・射程・ターゲット距離・減衰は全て同じワールド単位。配置の中心が自領域内なら境界をまたぐ配置円は許容する仮仕様。
- 領域は解析的な円の集合として保持。獲得した円は植物消滅後も保持。面積%の60×45サンプリングだけは表示上の近似で、配置判定には使わない。
- カーソル/タッチ位置に植物の当たり判定円と初期射程をプレビュー。緑=配置可、赤=重なり/境界/敵領域/資源不足等。座標と理由を表示する。
- マウスとtouchイベントのclient座標を現在canvasの矩形から変換。ResizeObserverでPane再表示・サイズ変更に追随。無効な0サイズでは入力を処理しない。
- PC操作優先。UI大改造、種族や属性追加、カメラパン/ズームは今回は行わない。

追加テスト: 任意の小数座標の無量子化保存、円同士の接線/epsilon/成長サイズ、盤面境界/NaN/Infinity、領域の解析的境界、画面offset・横長/縦長/スマホ幅・Pane再表示時の座標変換。同seedの小数座標入力で状態が一致することを確認。
