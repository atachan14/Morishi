# 個体から配置を選ぶための表示

新規・既存runの保存形式、能力、戦闘、乱数は変更しない。スキルカードは将来枠のまま。朝の新配置は `spaced-pockets-v1` を維持。

- PCの左右Paneは上52%を選択個体の独立スクロール領域とし、時計・敵一覧・比較設定は下へ移した。スマホは既存のPane切替を維持し、個体を最初に表示する。
- 手札・個体詳細・庭の身体を4属性の花弁に統一。花弁の大きさは各属性の最大値に対する比率。属性値と属性→能力の対応はバーと文字で確認する。HPや強さを花弁の面積だけから読み取る仕様ではない。
- 現在個体は基礎・現在直径による成長分・吸収ボーナスを属性ごとに分けて表示。受け手の属性対応は保存された対応を使う。
- 身体、射程R/2R、存在感R/2Rを実比率の図で比較。庭の選択対象と手札候補も射程Rを破線、2Rを点線で表示。手札候補の薄い青点線は接触なしで直径200に成長したときのRで、未来の生存や敵との到達を保証しない。
- 手札は現在の芽と直径200時の攻撃・防御・攻撃速度・射程・最大HPを並べる。能力は手札入り時に固定した値を使い、現在の育成ボーナスを再適用しない。
- 候補/ポインターが近い味方にある場合、2体が現在能力のまま接触した条件で、受け手、直径、攻撃、防御、速度、射程、存在感、最大HPを比較。コピー上で実際の `mergeContacts` を使い、時計・成長・ダメージを進めない。接触時刻・生存・周囲の連鎖は予測しない。合体上限を超える場合は予測を出さない。

人の試遊による分かりやすさ評価は未実施。特に接触比較は近くに候補を置いたときの条件付き比較であり、離れた味方へ将来接触する経路案内はしない。標準100%吸収の一部seedの停滞と長い待ち時間は、表示改善では解消していない。

検証：154テスト（合体比較の全吸収方針との一致・run非改変・受け手の対応保持・上限除外を含む）、TypeScript/Viteビルド。PC1366×768、スマホ390×844の隔離Edgeで個体表示と既存配置・保存・再開を確認。証拠は `evidence/ecosystem-identity/browser/`。

標準100%で停滞した新配置2seedも、全体の安全地点への別前線配置と合体支援に切り替える有限診断では勝利。局所探索への固定が原因のひとつだった。詳細は `ecosystem-spacing.md`。自動候補へこの診断方針を追加しておらず、手動で戦略を理解するための表示改善に留めている。

攻撃表示は後続の境界検証で、実際の0.1秒刻みの時計に合う攻撃間隔へ補正。戦闘ルールと保存は変えていない。最新の164テストと実時間確認は `ecosystem-boundary.md`。
